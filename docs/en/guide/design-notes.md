# 4-10 Design Trade-offs and Known Pitfalls

> What this solves: telling "the framework does this **on purpose**" apart from "this is indeed a pit". Do not "fix" the former; know how to work around the latter — read this chapter first when troubleshooting, and it saves half the blind guessing.
> Prerequisites: [Chapter 2-1 The Four Layers and Calling Rules](layers.md), [Chapter 4-9 Performance Tuning and Troubleshooting Handbook](troubleshooting.md). About 20 minutes.

## Minimal example

The decision order for "strange behavior" (follow it and you will basically never mis-edit the framework):

```php
// 1) get the facts first; do not guess first
Route::_()->getRouteError();                 // routing layer
\DuckPhp\Core\PhaseContainer::Dump();        // container/phase layer
var_dump(array_key_exists('我的选项', App::_()->options));  // did the option survive ('我的选项' = "my option")

// 2) check whether it is a deliberate design: §1 / §2 of this chapter + the comments and TODOs in src
// 3) deliberate → use it as designed; a real pit → work around it and record it in the maintenance guides
```

## How it works: deliberate design trade-offs (do not "fix" them)

| Design                                                                | Why it is done this way                                                      | The cost (you need to know)                                                                                                                                                     |
| ----------------------------------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **The four layers are a convention, not enforced**                                                    | No AOP/bytecode enhancement, zero runtime magic; overriding and replacement all rely on plain means like "class/file/singleton"                  | Layer violations do not error; overrides, multi-app setups, and test reuse just silently stop working ([Chapter 2-1](layers.md))                                                                                                               |
| **Phases + the mutable singleton `::_($new)`**                                         | Multiple apps in one process, with whole-instance replacement; simple to implement, intuitive to debug                               | Globally mutable state; tests and resident-run scenarios must clean up themselves ([Chapter 4-1](container-phases.md))                                                                                                          |
| **The option whitelist (`array_intersect_key`)**                                  | A component only accepts the keys it declares, so a misspelled key is not silently accepted                                      | **A misspelled key is dropped outright**, and the symptom is "I passed it but it has no effect" ([Chapter 1-5](configuration.md))                                                                                                     |
| **`$hidden_options` serves only as documentation metadata**                                     | Some keys are indeed read by the framework (e.g. `session_prefix`), but they are not wanted in the option tables                 | It **does not participate in the `$options` merge**: no default-value placeholder anymore, so read sites must be written as `?? <default>` (stated in the source comments)                                                                                                    |
| **Helpers are split by layer**                                                   | Using "method does not exist" to express the boundary is harder than rules in the docs ([Chapter 2-9](helper.md))                | A cross-layer call "finds no method" — that is a hint, not missing functionality                                                                                                                                   |
| **No PSR standards (no PSR-7/15)**                                         | Keeps zero dependencies and single-file embedding; requests/responses are arrays and simple objects                                 | Middleware is only a **compatibility layer** ([`Ext\MyMiddlewareManager`](../reference/Ext-MyMiddlewareManager.md)'s request is a `stdClass` by default) — do not force the Laravel / ThinkPHP / PSR mental model onto it ([Chapter 2-4](route-hooks.md)) |
| **Routing = convention + hook chains**                                                 | URLs map directly to `Controller\Xxx::method`; special cases go through hooks                    | No annotation routing; complex URLs use `route_map` ([Chapter 2-3](routing.md))                                                                                                           |
| **All system calls go through [`SystemWrapper`](../reference/Core-SystemWrapper.md)** | `header`/`setcookie`/`exit`/`session_start` are replaceable ⇒ tests and resident processes can run | Writing the native functions directly bypasses the wrapper, and tests cannot intercept them ([Chapter 2-17](testing.md))                                                                                                                 |
| **Error pages output placeholder text by default**                                                   | The framework does not guess your UI, but guarantees "no stack traces leaked" (when `is_debug` is false)                        | Without `error_404`/`error_500` configured you see the English placeholders ([Chapter 2-12](exception.md))                                                                                                |
| **Two mechanisms: settings and options**                                       | The former holds passwords/environments (read-only, from a file); the latter is whitelisted configuration in code                              | `Setting()` reads the **root app's** values; a child app that wants its own values must use options ([Chapter 1-5](configuration.md))                                                                                         |
| **No built-in ORM / CSRF / task scheduling / template engine**                                  | Keeps the size and controllability; each of these has a mainstream solution                                           | You pick and implement them yourself ([Chapter 2-18](security-performance.md))                                                                                                               |

## Common errors: known pitfalls (real problems — just know them)

| Pit                                                                                      | Symptom                                                                                                                      | Status / workaround                                                                                                                                                |
| -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Middleware short-circuiting is judged by the return value**                                                                            | When a middleware does not call `$next`: returning a response (a string) or `true` ⇒ handled (the controller no longer runs, and the manager `echo`s the string); returning `null`/`false` ⇒ treated as "not handled" and passed to the default route as usual | Deliberate: it leaves a buffer for "forgot to call `$next`" instead of suddenly white-screening. **This used to be a pit (short-circuit had no effect, the controller still ran, the response was discarded); fixed on 2026-09-26** ([Chapter 2-4](route-hooks.md) §5, [Chapter 4-13](ext-classes.md) §4) |
| `ZAllDemoTest` compares byte lengths                                                                   | It goes red after you change `src/`                                                                                                           | It compares the **byte lengths** of the demo output, and the `files` page dumps the option table / method table / call-stack line numbers ⇒ any method add/remove, line-number drift, or **an option moving between `$options` and `$hidden_options`** changes the length. Just update the expectations to the actual values ([Chapter 2-17](testing.md)) |
| There are **dead options** in demo/bin                                                                    | Passed but nothing happens                                                                                                                   | `cli_command_prefix` in `demo/public/dbtest.php` and `cli_command_classes` in `bin/duckphp` have no read site anywhere in `src/`                                                 |
| `demo/src/Controller/Commands.php` references a trait that does not exist                                       | A fatal error once it is loaded                                                                                                              | It has `use DuckPhp\Foundation\CommonCommandTrait;`, and that trait does not exist in the current `src/` — **do not copy this boilerplate** ([Chapter 2-16](cli.md))                                                |
| `demo/src/Model/CrossModelEx.php` does not live up to its name                                                 | Mistaken for a "cross-database model" example                                                                                                             | It contains only an empty `foo()` shell; for cross-database access use [`Helper::Db($tag)`](../reference/Db-Db.md) ([Chapter 2-8](model.md))                                                                 |
| [`RouteHookRouteMap`](../reference/Component-RouteHookRouteMap.md) does not support `Class::method` | Static-string callbacks have no effect                                                                                                              | The `::` branch in `adjustCallback()` is commented out; use `Class@method` or `Class->method`                                                                                    |
| The leftover `controller_prefix_post = 'do_'` in `Route`                                          | Confusing when you read the option table                                                                                                                 | The source carries `//TODO remove it`; what actually takes effect is `controller_method_prefix`                                                                                               |
| The semantics of `Route::forceFail()` is unfinished                                                            | You want to force the current route to fail                                                                                                               | The source has only `// TODO . force result ?`; currently it only works in combination with things like `defaultToggleRouteCallback(false)` ([Chapter 2-4](route-hooks.md))                                            |
| `view_skip_notice_error` defaults to `true`                                                     | Undefined variables in views raise no warning, and the page quietly misses a piece                                                                                                    | Turn the option off temporarily while developing to find the bug ([Chapter 2-6](views.md))                                                                                                                  |
| Omitting the view name at the root path looks for `Main/index`                                                                | Reports view not found                                                                                                                  | The route path of the root path is filled in from the welcome class; pass the view name explicitly ([Chapter 2-6](views.md))                                                                                                            |
| A child app's `is_debug` is an "OR" relation                                                                 | Stack traces visible in production                                                                                                                | `_IsDebug()` = setting or root or this app; **grep for `'is_debug' => true` globally before go-live** ([Chapter 2-18](security-performance.md))                                                      |
| `gen-reference.php verify` misses methods                                                       | Falsely reports correct documentation as "having extra methods"                                                                                                          | Big files with trait-alias overrides (e.g. `Core/App.php`); judge consistency by the drift scan ([Chapter 4-8](doc-maintenance.md))                                                                     |
| Neither docker test directory has `.sh` scripts                                                        | That set of start/stop scripts (which only ever existed in `docker/test-php84/`) has been deleted; both directories are pure Dockerfile + compose                                                   | Start with `docker-compose run --rm fulltest` ([Chapter 4-7](coverage.md) §4)                                                                                        |

## Common patterns: the decision flow and the discipline for changing the framework

### The "is this a bug" decision flow

1. **Get evidence**: `getRouteError()` / [`PhaseContainer::Dump()`](../reference/Core-PhaseContainer.md) / print the effective `options`;
2. **Check this repository's pitfall tables**: both maintenance guides have a "known pitfalls" table, and §2 of this chapter is the union;
3. **Check the source comments and TODOs**: the `$hidden_options` comment, `//TODO remove it`, `// TODO . force result ?` and the like all state the author's attitude;
4. **See whether it has a test**: if a test exists and asserts this behavior ⇒ it is probably deliberate (changing it means changing the test, and thinking through the blast radius);
5. **Still convinced it is a bug**: first write a test that reproduces it (and revert the bug to verify the test really goes red), then change the source; **after the change you must sync** `tests/` + `docs/zh/reference/` + `docs/zh/guide/`.

> Counterexample warning: [`Command::getCommandListInfo()`](../reference/Component-Command.md) has a `$phase` that is "read but not used" (a refactoring leftover). That kind **should be cleaned up in the source**; while something like [`App::Phase`](../reference/Core-App.md) hard-coded inside `Root($switch_phase)` is **deliberate behavior** that gets documented with a note of "the source wins".

### The discipline for changing the framework (this repository's conventions)

| Discipline               | Note                                                                                       |
| ---------------- | ---------------------------------------------------------------------------------------- |
| `src/` must be pure ASCII | After changing it, run `bash docs/scripts/check-non-ascii.sh` and expect `Total non-ASCII lines: 0` (Chinese appears only in `docs/`) |
| Changed `src/` → run the tests   | A single file day to day; the full run before committing ([Chapter 4-7](coverage.md))                                                    |
| Public renames sync the whole repo      | `src/` + `tests/` + `docs/zh/reference/` + `docs/zh/guide/`; after the change, leftover `grep` hits = 0             |
| A rename includes the "cleanup statements"   | E.g. the statements handling the option table in `App::__construct()`; an incomplete rename leaves invisible behavior differences                                        |
| Docs do not write "what will be"      | Only "what is now", with evidence (source file + line number)                                                                |
