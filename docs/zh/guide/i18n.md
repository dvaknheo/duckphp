# 21 国际化与文案

> 解决什么问题：让应用能按访客的语言显示文案——自动检测语言、按 key 取翻译、支持 `{name}` 占位符与 `[[key|fallback]]` 占位翻译。
> 前置：[第 5 章 配置与设置](configuration.md)、[第 11 章 视图与模板](views.md)。预计 15 分钟。
> 示例：`demo/view/main.php` 里有一行真实用法 `<?= __l("hello")?>`（视图侧就这么用）。`demo/` 里**没有**配套的语言文件，也没有完整的 i18n 演示页面——所以这一章的语言文件部分讲的是**约定**（工程自己按约定建 `config/lang/<locale>.php`），标注「示意」的代码段是写法示范。

## 最小示例

`demo/view/main.php`（真实文件）：

```php
<h1>Hello DuckPhp T: <?= __l("hello")?></h1>
```

语言文件按约定放在 `config/lang/<locale>.php`（下面是**示意**，工程里自己建；`demo/` 没有这个文件）：

```php
// MyProj 工程的 config/lang/zh_CN.php
return [
    'hello'   => '你好',
    'welcome' => '欢迎, {name}!',
    // …
];
```

于是：请求带上 `?lang=zh_CN` 时 `__l("hello")` 输出「你好」；**没有语言文件（或缺这个 key）时回落到原串**，也就是页面显示 `hello`——这也是排查「翻译没生效」的第一现场。

## 机制说明

### 入口：`__l()` → `CoreHelper::_L()` → `App::lang()` → `Lang::language()`

调用链（全部可 grep 核实）：

1. 全局函数 `__l($str, $args = [], $fallback = null)`（`src/Core/Functions.php` 第 15–18 行）；
2. `CoreHelper::_L()` 调 `App::_()->lang($str, $args, $fallback)`（`src/Core/CoreHelper.php` 第 144–147 行）；
3. `DuckPhp::lang()` 覆盖 `App::lang()`：若设了 `lang_handler` 选项则直接调它；否则调 `Lang::_()->language(...)`（`src/DuckPhp.php` 第 205–213 行）。

> 注意：`Helper` 各 trait（App/Business/Controller/Model）**没有** `Lang()` 静态方法。视图里用全局函数 `__l()` / `__hl()` / `__langtext()`，PHP 代码里用 `App::_()->lang(...)` 或直接 `Lang::_()->language(...)`。

### 语言检测的五级顺序

`Lang::detectLanguage()`（`src/Component/Lang.php` 第 151–170 行）按 `lang_detect_mode` 数组**依次**尝试，返回第一个非 null 的结果：

| 顺序 | 来源 | 选项 | 说明 |
|---|---|---|---|
| 1 | URL 参数 | `lang_url_param`（默认 `'lang'`） | `?lang=zh_CN` |
| 2 | Cookie | `lang_cookie_name`（默认 `'lang'`） | |
| 3 | HTTP 头 | — | 解析 `Accept-Language`，按 `q` 值降序取第一个 |
| 4 | CLI 环境变量 | — | 依次读 `LANG` / `LC_ALL` / `LC_MESSAGES` / `LANGUAGE`，去掉 `.UTF-8` 后缀 |
| 5 | 默认值 | `lang_default` | 兜底 |

所有结果经 `normalizeLocale()` 规范化：`zh-cn` / `zh_cn` / `zh-CN` 一律变成 `zh_CN`（语言小写、地区大写、分隔符统一为下划线）。

**短路规则**：`lang_final` 选项一旦在 init 时被算出（或你直接配置），后续请求不再重新检测。`lang_follow_root`（默认 `true`）让子应用直接采用根应用的 `lang_final`，不自己检测。

### 翻译文件目录约定

默认从 `config/lang/<locale>.php` 读（`lang_file_path` 选项默认 `'lang/'`，由 `Configer` 拼成 `{path_config}/lang/{locale}.php`）。文件返回 key→sentence 关联数组，value 里可写 `{name}` 占位符。

也可以**不走文件**：把句子直接写在选项 `lang_simple_mode_only_sentences` 里（`['zh_CN' => ['hello' => '你好']]`），适合无文件系统的场景。

### 占位翻译与回落链

`Lang::language($str, $args, $fallback)` 的查找顺序（`src/Component/Lang.php` 第 79–98 行）：

1. 当前 `lang_final` 对应的语言文件 / 内联句子里找 `$str`；
2. 找不到 → 查 `importDefaultSentences()` 注入的默认句子集；
3. 还找不到 → 用 `$fallback`（如果调用方传了）；
4. 没传 `$fallback` → **原样返回 `$str`**，并写一条 warning 日志（`No Language sentence Dectected ...`）。

`{name}` 占位符在命中翻译后做字符串替换；**没命中时不对原串做替换**（原串里没有 `{name}` 的语境下无影响）。

`replaceText()` / `__langtext()` 支持在**一段文本里**嵌 `[[key|fallback]]` 占位：`Lang::_()->replaceText('Use [[command.foo|foo]] mode')` 会把 `[[command.foo|foo]]` 换成 `command.foo` 的翻译（没有则用 `foo`）。

### `lang_handler`：完全接管翻译

设了 `'lang_handler' => callable` 后，`App::lang()` 直接调它，**不再走 `Lang` 组件**。适合接外部翻译服务或自己做 key 映射。`tests/DuckPhpTest.php` 第 107 行有真实用例。

## 常见写法

```php
// 1) 视图里翻译（最常用）
<h1><?= __l('welcome', ['name' => $user['name']]) ?></h1>
<?= __hl('welcome', ['name' => $user['name']]) ?>   <!-- 翻译 + HTML 转义 -->

// 2) PHP 代码里翻译
$msg = App::_()->lang('welcome', ['name' => 'Duck']);

// 3) 占位翻译：整段文案里嵌 key
$text = __langtext('Use [[command.foo|foo]] mode');
// 若 command.foo 有翻译则替换；没有则显示 fallback "foo"

// 4) 指定 fallback（语言文件没命中时显示它，不显示原 key）
$label = __l('custom_label', [], '自定义标签');

// 5) 注入默认句子（语言文件加载不到时的兜底）
Lang::_()->importDefaultSentences(['webinstaller.h1' => 'DuckPhp Web Installer']);

// 6) 自定义语言检测（示意：仓库里没有现成示例工程）
class App extends DuckPhp
{
    public $options = [
        'lang_default'     => 'zh_CN',
        'lang_detect_mode' => ['url', 'cookie', 'default'],  // 跳过 header / cli
    ];
}
```

## 常见错误

| 现象 | 原因 | 改法 |
|---|---|---|
| 永远显示原 key（如 `hello`） | 语言文件没加载到：路径错、文件名与 `lang_final` 不匹配 | 确认 `config/lang/zh_CN.php` 存在，且 `lang_final` 规范化后是 `zh_CN` |
| URL 加了 `?lang=zh_CN` 没效果 | `lang_final` 已在 init 时算好，运行期改 `$_GET` 不会重检 | 在**请求早期**（如 `onPrepare`）设 `$_GET['lang']`，或直接配 `'lang_final' => 'zh_CN'` |
| `{name}` 没被替换 | 该 key 在语言文件里**不存在**，回落到了原串 | 确认 key 在语言文件里；或传 `$fallback` 带 `{name}` |
| 子应用语言跟主应用不一致 | `lang_follow_root` 默认 `true`，子应用应跟随根 | 若要让子应用独立检测，给它配 `'lang_follow_root' => false` |
| 想完全接管翻译（如接外部服务） | 没有合适的挂点 | 配 `'lang_handler' => function ($str, $args) { ... }` |
| 语言文件里数组嵌套（如 `'user' => ['login' => '登录']`） | `Lang` 只做**扁平 key** 查找，不支持点号路径 | 把 key 扁平化（`'user.login' => '登录'`），或改用 `lang_handler` 自己解析 |
