# 1-1 DuckPHP 是什么

> 本章给你一个心智模型，读完就知道它和 Laravel / Yii2 / CodeIgniter 的差别在哪、适不适合你的项目。
> 预计 8 分钟。之后建议直接看 [第 1-2 章 安装与最小示例](install.md)。

## 一句话

DuckPHP 是一个**小内核 + 约定式分层 + 相位隔离**的 PHP 框架：内核只做「初始化、路由、请求分发」这些骨架的事，其余能力（数据库、缓存、多语言、用户体系…）都是可选组件；它不强制你用某个 ORM 或模板引擎，控制器里就是普通 PHP。

## 三个核心概念

只要记住这三句，后面所有章节都在这三句上展开：

**① 一个类就是一个单例**

所有框架类与工程类都通过 `ClassName::_()` 取实例，由「实例容器」统一管理：

```php
UserModel::_()->getUser(1);      // ✅
$m = new UserModel();            // ❌ 绕过了容器（相位、替换、测试注入都会失效）
```

**② 相位（Phase）= 实例空间**

同一个进程里可以跑多个应用，每个应用有自己的相位；同一个类名在不同相位下是**不同的实例**（第 3-1 章）。根应用相位是 `''`，子应用是 `:<name>`。

**③ Controller → Business → Model 单向调用**

分层是被强制的约定（第 2-1 章有「可调用/禁止」矩阵）：控制器收输入出输出、业务层放逻辑、模型层只管数据。视图里只用全局函数。

## 它长什么样（20 行跑起来）

一个文件就是一个应用 —— 这是仓库里真实存在的写法（`demo/public/helloworld.php`，有测试兜底：`ZAllDemoTest` 会请求它并比对输出）：

```php
<?php declare(strict_types=1);
require_once __DIR__ . '/../vendor/autoload.php';

// 单文件示例：把控制器也写在本文件里，于是把「控制器命名空间」设为根
class MainController
{
    public function index()
    {
        echo 'hello world';
    }
}

\DuckPhp\DuckPhp::RunQuickly([
    'is_debug' => true,
    'namespace_controller' => '\\',
]);
```

正常项目则是「一个入口 + 若干类文件」：`public/index.php` 里只有 3 行（第 1-2 章）。

## 和主流框架的差别

|         | Laravel                     | Yii2         | CodeIgniter 4       | DuckPHP                                                                                         |
| ------- | --------------------------- | ------------ | ------------------- | ----------------------------------------------------------------------------------------------- |
| 定位      | 全家桶                         | 全家桶          | 轻量 MVC              | 小内核 + 可选组件                                                                                      |
| 学习成本    | 高（容器/门面/Eloquent/Blade 都得学） | 高            | 中                   | 低（就那三个概念）                                                                                       |
| 依赖      | 强依赖 Composer 生态             | 较强           | 中                   | 无强制依赖，**单文件也能跑**                                                                                |
| 数据库     | Eloquent ORM                | ActiveRecord | Query Builder/Model | 直接用 PDO（[`Db`](../reference/Db-Db.md)/[`DbManager`](../reference/Component-DbManager.md)，无 ORM） |
| 模板      | Blade                       | PHP/小部件      | PHP                 | 原生 PHP 视图 + 全局函数（可换 [JsonView](../reference/Ext-JsonView.md)/EmptyView 等）                       |
| 多应用/多租户 | 需自行设计                       | 模块机制         | 需自行设计               | **内建**（相位 + 子应用，第三卷整卷讲这个）                                                                       |
| 覆盖第三方代码 | 服务容器绑定/扩展包 override         | 配置为主         | 配置为主                | 内建五个层次的覆盖（第 3-5 章）                                                                              |
| 适合      | 中大型团队项目                     | 中大型项目        | 中小项目                | 中小项目、需要多应用/多租户/挂载老项目的场景                                                                         |

**它不做什么**（诚实说）：没有自带 ORM、迁移工具、队列、模板引擎、任务调度；这些要么用 PDO/原生 PHP 解决，要么自己接第三方库（框架不拦你，因为不强制容器与约定）。

## 什么时候适合 / 不适合

**适合**：
- 想要「小、直白、可读」的代码，讨厌黑盒魔法；
- 需要**一个进程里跑多个应用**（前台 + 后台 + API + 第三方后台），并共享数据库/事件；
- 手里有现成的 DuckPHP 应用/老项目，要挂进新项目又不改它的代码；
- 要给 AI 或新同事一个「一眼能看懂调用链」的工程。

**不适合**：
- 团队已经重度投资 Laravel 生态（Eloquent / Blade / Horizon…）；
- 需要 ORM 自动建模、迁移、队列、广播等全套开箱能力；
- 追求「语法糖密度」而不是「显式调用」。

## 框架自带什么

| 类别          | 内容                                                                                                                                 |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 内核          | 应用初始化与生命周期、路由（含重写/映射/兼容模式）、请求分发、异常处理、相位容器                                                                                          |
| 常用组件        | 数据库（多库/读写分离）、Redis、缓存、日志、多语言、配置、验证器、分页、会话                                                                                          |
| 用户体系        | [`GlobalUser`](../reference/GlobalUser-GlobalUser.md) / [`GlobalAdmin`](../reference/GlobalAdmin-GlobalAdmin.md)（登录、注册、会话、权限、后台菜单） |
| 可选扩展（`Ext`） | JSON 视图、JsonRpc、中间件、权限菜单、安装器、SQL 导出、内嵌 HTTP 服务…                                                                                    |
| 助手          | 四层 `Helper` + 少量全局函数（`__h()` / `__url()` / `__res()` / `__l()`）                                                                    |
|             |                                                                                                                                    |

具体有哪些类、每个类有什么方法，查[参考手册](../reference/index.md)；本指南只讲怎么用。
